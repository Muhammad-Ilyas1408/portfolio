### 2026-11-07 — M8.6 fix: Reveal could leave content hidden after a fast scroll
- **Bug:** on the owner's idle machine, the screenshot test "credentials at 390px" ended with one `data-reveal="hidden"` element. Reproduced: a scroll that skips frames (big jumps on `/credentials` at 390px) left up to 10 `PageSection` reveals (the section headers and content blocks of Awards, Certificates, Specializations, Courses and Training) hidden for good. No element on the page is inside a `<details>` or a hidden container, or has zero height. **Cause:** the IntersectionObserver reports only changes it sees on a rendered frame. An element carried past the screen between two frames never "intersected", so no callback ever revealed it. The screenshot helper then scrolled each leftover into view and straight back to the top in the same task, so the last one never got a frame either.
- **Fix (`components/motion/Reveal.tsx`):**
  - The shared observer's root now extends 100000px above the screen (`rootMargin`, threshold 0), so anything on screen *or already scrolled past* counts as seen, and tiny or very tall elements always qualify.
  - Elements with no box (`display: none` above them) or inside a closed `<details>` are never hidden.
  - A safety-net sweep shows any hidden element that is on screen or above it, 3s after load or navigation and 200ms after scrolling stops (layout is read only then).
  - With JS off, under reduced motion, and for anything already on screen, the behaviour is unchanged.
- **Tests:**
  - New `tests/e2e/reveal.spec.ts`: on all 11 routes at 390 and 1440, fling to the bottom with no pauses, and assert nothing is hidden within 1.5s, which is shorter than the safety net, so the observer itself is tested.
  - New `tests/unit/reveal.test.tsx` (7 tests with a fake observer): the margin and threshold, hide then show, never hiding above the screen, `display: none`, closed `<details>`, and both safety-net sweeps.
  - The screenshot test is unchanged.
  - `contact.spec.ts` "zero axe violations…" now calls `test.slow()`, with the same assertions. It runs three axe scans: about 5s alone, but past 30s under full parallel load. It timed out in the first full run, and with the old Reveal it failed 11 of 12 under the same stress, so the timeout predates this change. For the same reason (30s timeouts, never violations), the full-page scans in `a11y.spec.ts` are `test.slow()` too.
- **Checks:** lint, typecheck, 182 unit tests and the build pass. The full e2e suite ran twice in a row: 199/199 and 199/199.
